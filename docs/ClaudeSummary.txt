  Case A — ["improving_pattern"], streak = 2, guided

  hint-fade IS allowed. improving_pattern increments ConsecutiveSupportFadeEligibleWindows, so 2 >= 2 passes. The
  hasStableMastery || hasImproving branch fires and adds hint-fade.

  Case B — ["recovery_pattern"], no improving, streak = 1

  hint-fade is NOT allowed. recovery_pattern falls into the else branch in ingestion, resetting
  ConsecutiveSupportFadeEligibleWindows to 0. After reset, 0 >= 2 fails. The hasRecovery branch runs but the gate blocks it.

  Case C — ["stable_mastery_pattern"], streak = 3, minimal

  hint-remove IS allowed. stable_mastery_pattern increments both streaks, so ConsecutiveSupportFadeEligibleWindows reaches 3
  >= 3. The hasStableMastery || hasImproving branch fires and adds hint-remove.

  ---
  Why this is more practical

  stable_mastery_pattern is the highest-confidence label the interpreter assigns — it requires multiple strong dimensions
  simultaneously and appears infrequently in real sessions. improving_pattern fires much more commonly as a learner trends
  upward but hasn't consolidated yet. By letting both labels contribute to the streak, the gate becomes reachable in realistic
   improving sessions (typically 2–3 consecutive improving windows) rather than requiring a level of confirmed mastery that
  only materializes late in a session or not at all.
