RECURSOR ENGINE — DEVELOPMENT ROADMAP (CURRENT STATE)

OVERVIEW
Recursor is an adaptive training engine that:
- captures user telemetry from simulations
- builds behavioral state representations
- applies adaptive interventions
- evaluates outcomes
- learns which interventions work, under which conditions, over time

The system evolves in layers:
1. Behavior understanding
2. Adaptation control
3. Policy learning
4. Temporal intelligence (in progress)
5. Continuous learning (future)

PHASE 10E — BEHAVIOR-STATE TEMPORAL PREDICTOR
Status: Implementation complete; live ADX audit, immutable model training,
medical-supply prediction validation, and cross-simulation validation pending.
Do not read this phase as fully validated — see "Next steps" below.
- Multiclass (struggling/recovering/stable/mastering/conflicted) SdcaMaximumEntropy
  model, all 3 horizons — first trainer to consume TargetBehaviorState
- Centralized BehaviorStateLabelPolicy (now in the Shared project so both Server and
  the Blazor dashboard client reference the exact same rules): distinguishes Missing
  (blank) from NoSignal ("unknown") from Invalid; no fabricated labels; canonical set
  unchanged from the existing MultiSignalGuardrailService vocabulary ("stable", not
  "steady"). TemporalEmbeddingService.BuildPredictionTargets normalizes through this
  policy before persisting TargetBehaviorState, and the dashboard's target-label
  rendering goes through the same policy instead of its own ad-hoc check.
- Session-level, grouped-stratified (by dominant label and SimId) train/validation
  split — not random row splitting. Explicit coverage reporting: classes/simulations
  absent from either side of the split are surfaced via CrossSimulationValidationStatus
  (Passed / InsufficientCoverage / NotApplicable) and recorded in the model manifest —
  combined metrics are never described as cross-simulation-validated when coverage is
  incomplete.
- Stored in TemporalBehaviorStatePredictions table, including per-class probabilities
  and a deterministic PredictionId (hash of SessionId+WindowIndex+Horizon+ModelVersion)
  for durable logical dedup across restarts/multi-instance replay — see
  docs/recursor-model-versioning.md.
- Model artifacts published as immutable version directories
  (Recursor/TrainingModels/versions/temporal-behavior-state/{version}/h{n}.zip +
  manifest.json), resolved by the runtime loader via the same layout the publisher
  writes to (previously these diverged — a published version was unreachable by the
  runtime resolver — see docs/recursor-model-versioning.md).
- Runtime inference gated by Recursor:Policies:EnableTemporalBehaviorStatePrediction
  (default false); dashboard model-comparison + coverage + confusion-matrix endpoints
  with simulation/scenario/model-version/horizon filtering; session timeline columns
  clearly labeled "shadow". A real end-to-end pipeline regression test confirms
  adaptation output (parameter changes, hint mode, difficulty, time pressure, error
  tolerance, guardrail decisions) is byte-for-byte identical whether this flag is on
  or off.
- Shadow-only; see docs/recursor-phase10e-behavior-state-temporal-predictor.md and
  docs/recursor-phase10e-behavior-state-label-policy.md
- Audit KQL (docs/kql/phase10e-temporal-behavior-state-target-audit.kql) has not yet
  been run against production ADX data — real label-quality numbers are a Phase 10F
  entry criterion, not yet known. No temporal-behavior-state model version has been
  trained/published in a live environment yet — the immutable-publish/runtime-resolve
  path is covered by a synthetic-data integration test only (see
  Stage3ModelPublisherResolverIntegrationTests.cs), not by a real training run.
